# Pitch 陀螺仪模式限位目标保持

## 问题

持续打满摇杆时目标呈锯齿：边界 `imu_offset + 机械限位` 里的坐标差
（`pitch_imu` 0x022 与 `pitch_mech` 0x023 两帧异步 CAN 的差）带噪声，
边界一动，被截断的目标就跟着跳，PID 被跳变目标反复激励。

## 现行为（边界保持）

分工：**下板管操作手语义，上板管物理可达性**。

下板 `Gimbal_Pitch_Update` GYRO 域：

- 目标贴到边界后锁存的是**数值本身**（`held_target`），不是边界公式。
  持续外打的增量当拍丢弃，边界再怎么抖都不改写目标——打满即给死。
- 反向输入当拍释放，目标立即跟随输入；回中保持不动。
- 释放的当拍按当前边界截断一次，目标回到可达区间。
- 切模式、休眠、反馈丢失时放弃保持，恢复后按当前反馈重建。

上板 `Gimbal_Mech_Target_Update` IMU 域补最终限幅（设计文档的
final authority），语义与下板同款：

- 坐标差 `imu_pitch - feedback_pitch` 先锁存（0.5° 迟滞 + 0.5° 内缩余量），
  不用每拍的采样时差去重写边界——实时差正是锯齿的耦合路径：云台一抖，
  IMU 与编码器的更新时差就调制边界，限幅啃目标，抖动自己养自己。
- 贴界后锁存的是数值本身：下板发来的目标继续外打则当拍丢弃增量，
  向内移动才释放，释放当拍按当前边界截断一次回到可达区间。
- 机械模式仍使用固定机械限位。

两板各自锁存各自的坐标差（下板异步两帧、上板同拍），数值可能差零点几度；
两板都只在贴界时截断且都保持数值，输出不会因此抖动。

## 已知取舍

- 外打保持期间车身大幅倾斜：目标暂不可达，两板都不提前改写
  （提前截断正是锯齿的来源），反向输入释放的当拍收口回可达区间。
  保持期间压到机械硬限位的部分由电机输出保护兜底，不是软件余量。
- 锁存阈值区分不了超过阈值的噪声与真实姿态变化；保持策略对此
  不敏感，但上板同帧采样的坐标差仍参与最终限幅。
- 两帧异步 CAN（0x022 IMU / 0x023 机械角）使坐标差带采样时差误差；
  设计文档原意是 0x022 同帧携带两值，尚未落实。
- 软件目标余量不能代替电机输出保护，也不保证机械运动没有超调。

## 验证

```powershell
python -m unittest discover -s test/gimbal -p test_pitch_limits.py
# 下板目标生成；上板最终限幅在 Up\RP27-Train_Template-C\test\gimbal
python -m unittest discover -s test/gimbal -p test_pitch_clamp.py
```

测试执行实际 `Gimbal_Pitch_Update`，覆盖双向打满保持、反馈抖动、
车身倾斜下保持与释放、行程内目标不跟随反馈、反馈丢失重建、
模式切换及键鼠输入。

烧录两板后固定底盘验证：到两端持续打满时看
`hero_gimbal.pitch.target_imu_angle`，必须是水平直线。
反向推杆立即离开边界。上板看 `gimbal.pitch.imu_angle_pid.target`
应同步平稳。
