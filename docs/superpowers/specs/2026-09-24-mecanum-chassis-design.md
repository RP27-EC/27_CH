# 四麦轮底盘控制设计

## 目标与范围

在现有 STM32H723、FreeRTOS 和 FDCAN 工程中实现四个 M3508 驱动的麦克纳姆轮底盘基础全向移动。四个电机连接 FDCAN1，反馈 ID 和机械位置依次为：

- 0x201：左前（FL）
- 0x202：右前（FR）
- 0x203：左后（BL）
- 0x204：右后（BR）

本阶段实现车体坐标系下的前后、左右平移和原地旋转，不实现云台跟随、小陀螺、功率限制或键鼠控制。

## 控制输入

- `ch3`：前后速度，正值表示前进。
- `ch2`：横移速度，正值的实际方向通过单处符号配置校正。
- `ch0`：旋转速度，正值的实际方向通过单处符号配置校正。
- 不设置摇杆死区，保留遥控器的原始零点响应。
- 三个通道均限制在 `[-660, 660]`；通道越界视为故障输入。

## 软件分层

### DeviceLayer

将 `chassis_motor.c/.h` 中不符合实车的八电机舵轮配置替换为四个 M3508 和一个 `Motor_RM_Group_t`。四个电机复用现有 `RM_Motor` 的反馈解析、速度 PID、电流换算及 FDCAN 组帧发送。

每个电机的 `rxId` 为 0 到 3，发送标准帧 ID 为 `0x200`。电机安装方向差异使用独立的轮向符号配置，不在运动学公式和 PID 中重复取反。

### ModuleLayer

`chassis.c/.h` 负责：

1. 保存归一化车体速度命令。
2. 执行 O 型麦轮逆运动学。
3. 按最大绝对轮速进行等比例缩放，保留速度方向比例。
4. 将四轮目标转速写入 `RM_Motor` 速度环并执行控制。
5. 在故障状态下清零目标、输出及 PID 状态。

该层不直接调用 HAL CAN/FDCAN API，不自行解析电机反馈，也不维护第二套速度 PID。

### ProtocolLayer

`can_protocol.c` 在 FDCAN1 收到 `0x201` 至 `0x204` 时，将报文分发给相应的四个底盘电机对象。现有云台电机分发保持不变。

### TaskLayer

`control_task.c` 每 2 ms 执行一次：

1. 检查遥控器在线状态和通道合法性。
2. 调用底盘控制更新，完成运动学和四个速度环计算。
3. 通过 `Chassis_Motor_Group.group_set_torque()` 发送一帧 `0x200`。
4. 故障时仍发送全零 `0x200`，确保电调及时卸力。

## 麦轮逆运动学

逻辑轮序固定为 `FL, FR, BL, BR`。使用车体命令 `vx`（向前）、`vy`（横移）、`wz`（逆时针旋转）计算：

```text
FL = vx - vy - wz
FR = vx + vy + wz
BL = vx + vy - wz
BR = vx - vy + wz
```

计算结果先整体归一化到最大绝对值不超过 1，再乘转子最大目标转速。由于 RM 电机反馈速度是转子 RPM，目标也统一使用转子 RPM；基础遥控模式不需要用轮周长和减速比换算线速度。

## 安全行为

- 初始化后所有目标与输出为零。
- 遥控器离线或通道越界时，四轮目标、电流输出和 PID 积分状态立即清零。
- 不需要额外拨杆使能；遥控器在线后可直接控制。
- 摇杆恰好为零时，速度闭环仍可输出制动力以维持零速；遥控器离线时则直接卸力。
- 单个电机离线状态保留用于监控，但基础实现不因一个反馈暂时丢失而驱动其他轮产生补偿动作。

## 验证

使用主机侧纯 C 测试验证不依赖硬件的运动学与安全逻辑：

- 零输入得到四轮零目标。
- 纯前进、纯横移、纯旋转的轮速符号组合正确。
- 混合输入超限时四轮等比例缩放。
- 遥控器故障时目标与 PID 状态清零。

随后使用 Keil 工程进行全量编译检查。实车首次上电应架空底盘，以低目标转速逐项核对四轮位置和方向；轮向不符时只调整对应的轮向符号配置。
